
# humanWeb · GPT-5 + Chrome DevTools Research Assistant 🤖

humanWeb has been rebuilt from the ground up to pair OpenAI's GPT-5 model with first-class Chrome DevTools instrumentation. The assistant now plans research strategies, drives a headless Chrome session via the DevTools protocol, captures performance artefacts, and assembles a professional-grade report with inline citations.

## Highlights

- **GPT-5 reasoning** – prompts are executed through the [`responses` API](https://platform.openai.com/docs/guides/responses) providing richer reasoning controls and structured outputs.
- **Chrome DevTools integration** – browsing is powered by Playwright's Chromium driver with direct DevTools access for performance metrics, network captures, screenshots, and traces.
- **Automated research loop** – GPT-5 generates a search plan, audits each source, and synthesises findings into an executive brief.
- **Quality gate** – every report is reviewed by a dedicated GPT-5 critic that scores coverage and recommends improvements.

## Requirements

- Python 3.10+
- Node.js 20.19+ (required by Playwright and optional `chrome-devtools-mcp` tooling)
- Google Chrome / Chromium stable
- An OpenAI API key with access to `gpt-5`

## Installation

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium
```

Create a `.env` file in the project root:

```text
OPENAI_API_KEY=sk-your-key-here
```

## Usage

```bash
python humanWeb.py
```

You'll be prompted for:

1. **Websites per query** – how many Google results to audit.
2. **Research objective** – the primary question GPT-5 will explore.
3. **Follow-up searches** – how many additional queries the planner should schedule.

The assistant will:

1. Generate a sequenced search plan with GPT-5.
2. Use Chrome DevTools to gather page text, screenshots, traces, performance metrics, and network logs for each result.
3. Ask GPT-5 to extract unique insights per source.
4. Synthesise an executive report with inline citations.
5. Run a quality review and save both the report and critique.

Outputs are stored in:

- `Searches/<topic>/` – raw captures, DevTools artefacts, and per-source summaries.
- `Reports/<topic>/` – the consolidated report.
- `QA/<topic>/` – the quality review markdown.

## Chrome DevTools MCP (optional)

The project works out of the box with Playwright's embedded DevTools client. If you want to expose the browser to an external coding agent (Gemini, Claude, Cursor, etc.), configure the [`chrome-devtools-mcp`](https://www.npmjs.com/package/chrome-devtools-mcp) server and reuse the captured artefacts.

`~/.config/<your-mcp-client>/config.json`

```json
{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": [
        "-y",
        "chrome-devtools-mcp@latest",
        "--headless=true",
        "--isolated=true"
      ]
    }
  }
}
```

With the server running you can reuse traces (`*_trace.zip`) and screenshots generated by humanWeb or let your MCP-aware assistant take additional actions inside the same Chrome profile.

## Troubleshooting

- Ensure `playwright install chromium` has been executed once per environment.
- If Google challenges automation, set `headless=False` in `humanWeb.py` to inspect the session.
- Use the saved DevTools traces to diagnose slow pages via `playwright show-trace <trace.zip>`.
